# 02 — 验收判据

## 1. 五级闸门

| 级别 | 判据 | 失败处理 |
|---|---|---|
| **T0 契约** | W12 解码逐位等于 checkpoint；树 kernel 在链上与 stock 逐位一致；option default 复现 stock | 不进测量 |
| **T1 dev token forcing** | rate rule 0.5pt@95%CI + event rule（2*delta，二项检验） | 退回修改 |
| **T2 晋升** | 95% LB > 1% + 2x 噪声；有输出分歧则 > 3% | 不合并 |
| **T3 sealed final** | 未见请求配对计时 + 4096 token 输出重跑 token forcing | 整轮作废 |
| **T4 迁移** | 条目单独作用于 stock 必须复现源系统代码；复用需重调重测且不计新发现 | 条目不入库 |

## 2. 两条论文级验收

这两条是评审最会打的点，也是"复现架构"与"复现数字"的分水岭。

### 2.1 ceiling 一致性

每轮声称的瓶颈必须被下一轮的实测 profile 迁移证实。

核对方式：附录 A3 的 15 次晋升增益连乘应约等于 sealed 的 2.13×。若连乘显著偏离，说明
中间的测量口径变过（换了 stock 配置、换了请求集、或噪声标定失效）。

### 2.2 故障注入回归（复现 Fig 4）

对每第 7 个 vocab id、2048 token 之后加 logit bias = 2：

- **必须**被 event rule 拒绝（论文：200 个审出事件中 192 / 191 个无法解释）
- **同时**任务精度区间仍与 lossless 重叠（这正是"精度不能当验收"的证据）

若你的评测器能靠任务精度发现故障，说明注入太强，测的不是论文的工况。

## 3. 基线锁定的纪律

论文的增益有相当部分来自"stock 在每个 GPU/regime 上被调到最好"：

- PRO 6000 上最佳 stock 用 block 12 + Triton attention，比 H100 配置快 9.9%
- H100 上 stock DFlash2 用训练时的 block size
- 没有任何 EAGLE-3 配置能超过默认 2.4%
- 单请求 H100 上，stock + DDTree 树是更强基线（4.82× over AR），SpecPilot 比它快 1.84×

复现时 stock 配置必须**一次性锁定并写进账本**，否则增益数字可以任意滑动。这是最容易
被无意破坏、也最容易被质疑的一条。

## 4. 测量纪律

| 项 | 要求 | 理由 |
|---|---|---|
| 配对 | 双卡、同请求、互换 GPU、两轮 | 单卡串行无法把噪声压到 0.1% |
| 噪声标定 | 每次会话先跑 stock vs stock | 门槛是 1% + 2x 噪声，噪声必须先量 |
| 请求集 | dev / sealed 物理隔离 | sealed 泄露 = 整篇结论失效 |
| 聚合 | 每 benchmark 几何平均，再等权几何平均 | 论文口径 |
| 交错 | AR / stock / SpecPilot 交错跑 | 消除时钟漂移 |

## 5. 复现自身的前置自检

在测量任何真实系统之前，必须先通过：

1. **假阳性测试**：注入 logit bias 的系统被拒（event rule 触发）
2. **假阴性测试**：只改浮点归约顺序的等价实现被接受（rate rule 不触发）
3. **噪声测试**：stock vs stock 的 95% 区间宽度 < 0.2%
4. **可复现测试**：同一 patch 连测两次，判定一致

四条全过，才允许开始 Phase 0。
