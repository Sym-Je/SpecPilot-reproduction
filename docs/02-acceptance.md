## 1. 五级闸门

| 级别 | 判据 | 失败处理 |
|---|---|---|
| **T0 契约** | 对所实现机制验证相应正确性契约，如W12逐位还原、树kernel链上等价；option default复现stock。本级为本地工程验收 | 不进测量 |
| **T1 dev token forcing** | rate rule 0.5pt@95%CI + event rule（2*delta，二项检验） | 退回修改 |
| **T2 晋升** | 收益的95% LB > 1% + 2×实测噪声；输出有分歧时论文要求约3%，实现口径见下文；T1未过不能晋升 | 不合并 |
| **T3 sealed final** | 未见请求、两次配对运行并换GPU；常规输出和更长至4096 token输出重跑token forcing | 正确性或性能任一未过即拒绝final |
| **T4 迁移** | 条目连同其依赖作用于stock后，必须准确还原源系统代码；复用需重调重测且不计新发现 | 条目不入库 |

T2比较的是`LB(speedup) - 1`与提升阈值，不是把speedup本身与1%比较。
本地HTTP诊断当前采用`max(0.01 + 2 * noise, 0.03)`处理输出分歧；这是对论文“约3%”的
保守实现选择，不应伪称论文给出了该精确max公式。性能接口的promoted也不替代真实正确性及正式晋升。

## 2. 方法复现与正确性核查

以下区分机制一致性证据与论文观测结果，不能用跨协议数字相等作为伪验收。

### 2.1 ceiling 一致性

记录每轮瓶颈估计、实测profile和优化后变化，核查证据是否支持假设。
瓶颈没有迁移本身不等于正确性失败，也不能为了符合预期而修改profile结论。

逐次晋升只有在同一请求、指标及基线链上才可能作乘积一致性检查；附录A3的dev晋升
与独立sealed测量不是同一协议，不能要求连乘等于sealed的2.13×，也不能据偏离直接判定计时失效。
ceiling/profile核对需要实测瓶颈证据；2.13× [2.07,2.19]是本部署sealed参照，
不是要求我们的CI逐端点相同。独立数字复现的等效容差与功效须在揭盲前由维护者/用户确定。

### 2.2 故障注入回归（复现 Fig 4）

对每第 7 个 vocab id、2048 token 之后加 logit bias = 2：

- **必须**被 event rule 拒绝（论文：200 个审出事件中 192 / 191 个无法解释）
- 同时记录任务精度区间，但不能用任务精度代替token forcing。

论文报告故障实现的任务精度区间与lossless重叠，这是该实验的观测结果，不是任意复现都
必须得到的通过条件。若本地任务精度能发现故障，应核对注入/样本/区间并如实报告，
不能因此自动认定注入过强，也不能反向调参追求重叠或精确的192/191事件数。

scorer必须沿待测系统自身输出上下文使用stock引擎和FP32 LM head评分。stock mismatch及δ
需本机标定；δ按stock首次偏离AR的最大margin向上取整到1/8倍数。论文0.72%不是本地硬编码常量。
rate rule与大margin event rule独立，事件解释需stock路径/相同margin或prefill长度敏感性的证据。

## 3. 基线锁定的纪律

论文的增益有相当部分来自"stock 在每个 GPU/regime 上被调到最好"：

- PRO 6000 上最佳 stock 用 block 12 + Triton attention，比 H100 配置快 9.9%
- H100 上 stock DFlash2 用训练时的 block size
- 没有任何 EAGLE-3 配置能超过默认 2.4%
- 单请求 H100 上，stock + DDTree 树是更强基线（4.82× over AR），SpecPilot 比它快 1.84×

复现时 stock 配置必须**一次性锁定并写进账本**，否则增益数字可以任意滑动。这是最容易
被无意破坏、也最容易被质疑的一条。

## 4. 测量纪律

| 项 | 要求 | 理由 |
|---|---|---|
| 配对 | 双卡、同请求、互换GPU；论文sealed用两次配对运行 | 控制卡位与请求差异；不保证某个固定噪声上限 |
| 噪声标定 | 用匹配部署及测量协议的stock vs stock实测噪声；本地每会话校准方案须预登记 | 将实际噪声计入晋升阈值，不能硬抄论文数值 |
| 请求集 | dev / sealed 物理隔离 | sealed 泄露 = 整篇结论失效 |
| 聚合 | 每 benchmark 几何平均，再等权几何平均 | 论文口径 |
| 交错 | 论文的AR对照在dev上交错跑AR/stock/SpecPilot | 减少时钟漂移；dev结果不能冒充sealed |

论文§5.1的增益口径：每benchmark、每batch size先对逐请求输出速率比作几何平均，
再等权几何平均。物理轮次必须保留在同一请求cluster内，不能把20请求×4轮当80独立请求。
request-cluster分层bootstrap、迭代数、随机种子及精确CI尾概率是本地实现选择，论文未完整指定；
正式95%下界的口径须写清，不能把双侧95%CI与单侧95%下界不加说明地混用。

## 5. 噪声、区间与额外自检

论文§3.2的“stock-versus-stock noise (<0.1% for one request on H100)”是**论文报告的观测值**，
不是要求所有部署必须低于0.1%的通用通过条件。论文没有规定95%CI全宽<0.2%，
也没有规定两个独立null会话的CI必须都覆盖1。

对stock/stock比值区间`[L,U]`：

- 全宽是`U - L`。
- 本地null诊断当前的noise是`max(abs(L - 1), abs(U - 1))`，同时包含区间宽度与离1偏移。
- noise不是全宽，也不必等于半宽；论文没有给出该精确估计公式，不能将其冒充原文定义。
- 本地不同路径使用的中位数/几何均值CI，以及另一个CV辅助函数不能按同名noise混用。
  正式校准须由维护者绑定估计量、请求规模、轮次、会话选择规则及适用候选协议。
- 未解释偏移、漂移和丢项仍须报告与调查；取消固定宽度门槛不等于允许无效区间或挑选会话。

**不再将 CI 全宽 <0.2% 或 CI 覆盖1作为通用研究前置门槛**；它们是本地工程诊断，
不是论文硬门槛。不得仅为了满足它们而无限重跑，也不能把统计噪声直接解释成模型答案错误。
更高的有效实测噪声应进入更保守的晋升阈值，不应通过缩小noise、删请求或后验改协议掩盖。

历史字段`precision_passed`（全宽<0.002）、`centered`（覆盖1）、`stable_passed`（两者同时满足）
及既有独立门禁仍保持原含义与返回值；当前controller尚未切换策略，这些字段不能冒充
paper-aligned-v1的完整验收结果，也不能在harness另设正式裁判绕过controller。

## 6. 必保留的正确性与执行自检

1. **假阳性测试**：注入 logit bias 的系统被拒（event rule 触发）
2. **假阴性测试**：只改浮点归约顺序的等价实现被接受（rate rule 不触发）
3. **校准证据**：同尺度stock null的原始配对、区间、noise、会话/卡位与偏移报告完整。
4. **可复现测试**：同一patch在预登记重复中判定一致；这属于本地工程检查，不冒充论文固定次数要求。
5. **完整性**：拒绝空请求/空token、缺项、身份漂移、非法速率及半对；真实配对不能由单卡串行代替。

真实正确性与正式晋升前必须具备对应证据；mock、同臂输出一致或吞吐提高都不能代替。
CPU独占不是论文规定的前置条件，只有出现可检验的资源干扰假设时才作为诊断选项。
下一步是维护者确认并接入上述正式校准/判定口径，补真实scorer/δ/故障注入；
本次文档修订本身不授权修改controller、候选晋升、sealed或RSI。
